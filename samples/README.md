# テスト用 CSV サンプル

脆弱性検査ツール（外部攻撃面管理 / ASM）からエクスポートされる「脆弱性全件 CSV」を**模したダミーデータ**です。実データは含みません。すべて `example.com` 系の架空資産・公開 CVE 番号で構成しています。

> ⚠️ 列名・値の形式はあくまで想定です。実ツールの正式な列名（特に `Issue Instance ID`）が判明したら差し替えてください。

## ファイル

| ファイル | 用途 |
| --- | --- |
| `scanner-export-2026-05.csv` | 月次取込の1回目（基準データ） |
| `scanner-export-2026-06.csv` | 月次取込の2回目（差分テスト用） |

## 列構成

| 列名 | 説明 |
| --- | --- |
| `Issue Instance ID` | 突合キー（一意）。Mikke の `IssueInstanceId` にマッピング |
| `Title` | 脆弱性名 |
| `Severity` | Critical / High / Medium / Low / Info |
| `Status` | 検査ツール側ステータス（open / resolved 等）→ `ScannerStatus` |
| `Asset` | 対象資産（ホスト名 / FQDN） |
| `CVE` | 関連 CVE |
| `First Seen` | 初回検出日 |
| `Last Seen` | 最終検出日 |
| `CVSS` | CVSS スコア |
| `Category` | 分類 |
| `Port` | 対象ポート |

## 差分テストの観点（5月 → 6月）

このサンプルは Mikke の取込ロジック（機能設計書 §2・§9）を検証できるよう、以下のケースを意図的に仕込んでいます。

| Issue Instance ID | 5月 | 6月 | 期待される検知ステータス遷移 |
| --- | --- | --- | --- |
| `IID-1001` | あり | あり | 新規 → **継続** |
| `IID-1002` | あり | あり | 新規 → **継続** |
| `IID-1003` | あり | **なし** | 新規 → **未検出(New)** |
| `IID-1004` | あり | あり（Severity 変化） | 継続（検査ツール由来の列が更新される） |
| `IID-1005` | **なし** | あり | （6月で）**新規** |
| `IID-1006` | あり | あり | Critical（条件一致で自動管理対象） |

※ 「再検知」は、5月で未検出化 → 7月に再登場、のように3か月以上のサンプルが必要なため、運用テスト時に手動で確認してください。
